# Фронтенд Task Hub и подключение API

Интерфейс подключён к актуальному backend из `main`. Серверные контракты описаны
в [API.md](API.md), схемы находятся в `src/shared/contracts.ts`.

## Запуск

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

По умолчанию используется настоящий API того же приложения Next.js. Отдельный
backend-процесс не нужен. Задачи, команды и отклики берутся с сервера; изменения
записываются в `data/db.json`. Первый запрос создаёт демонстрационную базу.

Локальные настройки в `.env.local` (этот файл игнорируется Git):

```dotenv
NEXT_PUBLIC_DATA_MODE=api
NEXT_PUBLIC_API_BASE_URL=
AI_PROVIDER=mock
DATA_FILE_PATH=./data/db.json
```

`AI_PROVIDER=mock` означает только шаблонные AI-ответы. Хранилище, рейтинг,
публикация и отклики работают через настоящий backend. Мастер показывает
`ai.warning` при каждом AI-ответе, в том числе при fallback.
Доступность внешней модели `/api/health` не проверяет.

Для внешнего AI нужно локально задать `AI_PROVIDER=openai`, `OPENAI_API_KEY`
и `OPENAI_MODEL` по настройкам backend, затем перезапустить сервер. Секреты
не должны иметь префикс `NEXT_PUBLIC_` и не попадают в браузер.

## Как устроено подключение

Все компоненты обращаются к `TaskService` из `src/lib/client/service.ts`.
HTTP-адаптер использует общие Zod-схемы, снимает обёртки `{task}`, `{tasks,total}`,
`{teams,total}`, `{proposal}`, `{proposals,total}` и сохраняет метаданные AI.
Frontend не импортирует серверные модули (кроме изолированных интеграционных тестов).

- Кабинет: `GET /api/tasks?status=all`; каталог: `GET /api/tasks`.
- Ответы мастера преобразуются в массив `{field, answer}`, отрасль — в `fields.industry`.
- Выбранная отрасль передаётся и при анализе описания, чтобы AI не спрашивал её повторно.
- Вопросы и ответы привязаны к исходному описанию и отрасли. Изменение любого из
  этих значений сбрасывает предыдущие уточнения с видимым уведомлением.
- Ручное заполнение доступно прямо на шаге вопросов, в том числе после ошибки AI:
  непустые ответы переносятся в карточку, но требуют подтверждения человеком.
- Сохранение отправляет плоские поля и `confirmedFields`; редактирование добавляет
  `expectedVersion` из последнего сохранения.
- Черновик можно сохранить без названия; для публикации название необходимо
  заполнить и подтвердить. Ограничения длины в мастере берутся из общих схем API.
- После первого сохранения открывается постоянный `/business/tasks/{id}/edit`.
  Если черновик создан, но публикация завершилась ошибкой, редактор также открывается
  по постоянному адресу с предупреждением и актуальными серверными данными.
- Публикация отправляет `{confirmed:true, expectedVersion}` только после явного
  согласия человека и подтверждения названия. Любой рейтинг допустим.
- Обновление уже опубликованной задачи завершается успешным `PATCH`: повторный
  запрос публикации не нужен, поскольку сервер сохраняет статус `published`.
- Сохранённые баллы и разбор берутся из ответа сервера; до сохранения показывается
  предварительный рейтинг по общей конфигурации `shared/scoring.ts`.
- Ошибка версии сохраняет введённый текст в форме. Пользователь может скопировать
  его и явно загрузить актуальную карточку. Автоматической перезаписи чужих правок нет.
- В кабинете можно архивировать задачу после отдельного подтверждения. Запрос
  передаёт `expectedVersion`; при конфликте список перечитывается. Архивные
  карточки и история откликов доступны для чтения, новые изменения закрыты.
- Решения по откликам: `accepted` или `rejected`. Можно изменить решение и выбрать
  несколько команд. Возврат в `pending` не предусмотрен серверным контрактом.
- При смене решения сохраняется существующий комментарий бизнеса.
- Если задача архивирована в другой вкладке, ошибка API обновляет её статус
  в интерфейсе и закрывает недоступные действия.
- Ошибки API и валидации показываются в форме, без скрытого перехода на заглушки.
  При недоступности AI можно заполнить карточку вручную.

Backend пока не содержит API этапов и баллов команд. Эти элементы скрыты в режиме
`api`; несуществующие endpoints не вызываются. Создание профиля команды через API
поддерживается сервером; текущая форма отклика выбирает один из имеющихся профилей.
Авторизации нет: кабинет бизнеса и выбор команды — демонстрационные роли.

## Автономный режим

При необходимости можно явно установить `NEXT_PUBLIC_DATA_MODE=mock` и
перезапустить dev-сервер (production нужно пересобрать). Тогда данные остаются
только в localStorage `ai-sana-demo-v1`, доступны локальные демонстрационные этапы.
Старые данные первой версии фронта читаются с миграцией в памяти и не удаляются.
Этот режим не синхронизируется с серверной базой и не включается при ошибках API.

## Экраны

| Путь                            | Экран                                                   |
| ------------------------------- | ------------------------------------------------------- |
| `/`                             | Главная, пример рейтинга, актуальные задачи и ввод идеи |
| `/catalog`                      | Опубликованные задачи, поиск, фильтры и сортировка      |
| `/business`                     | Кабинет со всеми статусами задач                        |
| `/business/new`                 | Описание → вопросы → редактируемая карточка             |
| `/business/tasks/:id/edit`      | Правки, подтверждения и публикация                      |
| `/business/tasks/:id/published` | Результат публикации                                    |
| `/tasks/:id`                    | Карточка и форма предложения команды                    |
| `/business/tasks/:id/proposals` | Отклики и ручные решения                                |

Логотип Task Hub (`public/logo.png`) расположен в шапке и подвале. Исходное
изображение имеет большие поля: CSS ограничивает видимую область и адаптирует
цвета для тёмной темы. Исходный PNG сохранён. `public/hackalem-ai.png` стоит
компактно в подвале, с подписью «Создано на хакатоне».

## Проверка

```powershell
pnpm check
pnpm test:smoke
```

HTTP smoke-тест запускает отдельный production-сервер на временной базе.
`src/lib/client/service.test.ts` проверяет клиентский адаптер против реальных
сервисов backend с изолированным хранилищем: форматы запросов, метаданные AI,
публикацию, версии, отклики, решения и обработку ошибок. Платные AI-запросы
в автоматических тестах не выполняются.

`src/lib/client/builder-draft.test.ts` проверяет сброс старых ответов при смене
исходных данных, сохранение ответов при возврате без правок и перенос данных
в ручной редактор. После изменений мастера дополнительно проверьте в браузере:

1. Ответить на вопросы кофейни, вернуться назад, заменить описание каталогом кружков:
   старые ответы и контакт не должны попасть в новую карточку.
2. После сбоя генерации выбрать «Продолжить вручную с моими ответами»: введённые
   результат, данные и контакт должны остаться в соответствующих полях.
3. Сохранить новый черновик и обновить страницу: адрес и заполненная карточка сохраняются.
4. Убедиться, что успешная публикация по-прежнему открывает экран подтверждения,
   а сбой публикации после создания черновика не оставляет `/business/new`.

Ручной сценарий: «Создать задачу» → пример кофейни → вопросы → вставить пример
ответов → собрать карточку → проверить название → подтвердить сведения и согласие
на публикацию → опубликовать → открыть как команда → отправить предложение →
открыть отклики как бизнес → выбрать команду → перезагрузить страницу.
